# 测试约定

- 测试保护行为：输入输出、状态变化、数据迁移、并发隔离、取消、权限、内容安全与导出格式。普通标题、按钮文字、占位提示、加载提示的措辞不作为验收条件。
- 界面优先检查原生属性、角色、已有业务标识、选中或禁用状态、结果数据及来源。不要匹配整段页面、样式类串或页面快照；不要为了测试普通文案新增依赖或修改业务结构。
- 可以检查测试主动传入的文字是否正确显示、转义或导出，这与锁定产品文案不同。错误测试优先保留模拟错误的原始原因，不固定产品添加的提示前缀。
- 测试名称声称保护的行为必须有对应验证。替换文案断言时应验证实际功能；仅检查“页面非空”不能代替按钮可用、数据正确等验证。
- 必要风险提示必须验证相应条件下会出现；允许改写措辞。模型提示词、协议字段、引用编号和导出格式可能影响行为，不能按普通界面文案批量删除；精确匹配只保留必要片段，并说明保护的约定。
- 纯文案或样式调整通常不新增测试。新增功能或修复缺陷时，优先补入对应的现有测试文件；用最小场景覆盖真实风险，不追求测试数量。
- 测试应离线、可重复，不访问真实站点、模型服务或用户存储，不产生付费请求。不要安装依赖或启动开发服务；依赖缺失时将所需命令交给用户。
- 单元测试只模拟当前职责需要的依赖。新依赖已有独立覆盖时，入口时序测试可模拟该模块，避免不断补造无关的浏览器页面能力；集成测试仍需验证真实模块间的连接。

## 本地验证

在 `extension` 目录使用已有依赖执行：

- 局部修改：`pnpm test tests/ai-panels.test.ts`（替换为相关测试文件，可传多个）。
- 提交前涉及多模块：`pnpm test`。
- 类型或接口变化时增加：`pnpm typecheck`。

先运行相关测试；通过后仅在影响范围需要时扩大验证。不要因修改测试而自动更新所有预期值或跳过失败用例；先区分文案变化、真实回归与环境限制，并如实报告未完成的验证。
