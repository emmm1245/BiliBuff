确认日期：2026-10-17。状态：阶段0–6的代码重构与本地基本验收已完成，实际扩展加载及真实模型回归尚未验证。用户随后要求连续完成、各阶段自行简单验收；本轮据此完成类型、规范、模拟回归和两种浏览器的本地编译，没有下载依赖、启动扩展或调用真实模型。

## 目标与范围

按功能整理模块，统一模型调用、数据校验和界面组件，降低后续功能开发的重复工作。保留现有功能、主要入口、数据兼容及调用条件；界面保持像B站的蓝粉配色、中性底色与操作气质，控件和交互可采用组件库实现。

范围覆盖后台、设置页、推荐过滤、观看统计、留白搜索、计划分析、两种复核、评论采集与速读、视频字幕与分析、播放器接入、下载、备份、主题及调试日志。逐阶段替换实现，每阶段保持扩展可用。

本轮不增加新业务功能，不批量接入尚未使用的供应商，不增加全局状态管理、数据库封装或智能体框架。现有数据库结构、存储键和备份格式先保持兼容；以后确需改变时，单独设计迁移与回退。

### 源码组织

在现有源码根目录下，以功能模块、平台能力和共用界面组织代码；扩展入口目录继续沿用框架约定。

- 功能模块：内容过滤、观看统计、留白搜索、计划分析、复核、评论、视频助手、设置与维护。一个功能的纯逻辑、状态协调、结构校验和界面尽量相邻。
- 平台能力：扩展消息、配置读写、数据存储、权限、模型适配和日志连接。平台层不依赖具体页面组件。
- 共用界面：基础控件、AI展示、主题及隔离挂载。业务专用的章节、评论和建议操作放回对应功能。
- 测试：沿用现有测试入口，按功能对应组织。小模块无需强行拆成多层；出现多个真实使用者后再抽公共代码。

依赖从入口到功能，再到公共能力。网页侧不得因为导入公共类型或规则函数，连带引入密钥读取、后台存储实现或完整模型工具包；重型渲染能力只在需要的界面加载。

## 模型调用与数据校验

### 共用模型调用

共用层统一服务选择、生成参数、取消、超时、错误转换及日志，具体采用下文[AI SDK v7现成功能对照](#ai-sdk-v7现成功能对照)。优先直接使用已提供的调用、输出和状态能力，公共适配仅连接本项目权限、配置、错误文案与存储，不再复制一套同形接口。功能模块提供提示词、输入和结果要求；供应商专属参数由对应适配处理，不把不同供应商的思考与结构化能力强行视为相同。

使用AI SDK的模型调用显式设置 `maxRetries: 0`【关闭请求自动重试】；省略 `streamRetries`【禁用流开始后的重试能力】，错误回调不返回重试指令。兼容服务不能因格式不支持就悄悄追加一次付费请求；错误交给用户处理。实际支持的格式在接入时确认。独立决策协议同样保持不自动重试。

| 功能 | 输出方式 | 完成条件 |
| --- | --- | --- |
| 视频总结、问答 | 正文流式输出 | 正常结束，正文非空；问答引用通过业务检查 |
| 计划分析、评论速读 | 结构化结果，生成中预览说明 | 完整结构通过校验，再检查词条操作、引用与会话有效性 |
| 视频章节、通用复核 | 完整结构化结果 | 正常结束且所有章节范围或分类项有效 |
| 阿里云决策复核 | 独立协议适配 | 保留概率阈值与保守判定，复用公共日志和错误处理 |

保持现有任务超时设置，迁移时核对取消、断流、服务拒绝、输出截断、仅有思考内容等状态。预览不能进入正式缓存或成为可采用建议，失败或取消保留上次完整结果。

在调用层记录实际发送的参数与原始响应，生成中仍能导出已保存日志；日志失败不阻断模型业务，清除日志后旧任务不能重新写回。认证头和其他服务密钥不得进入日志。

后台任务继续沿用既有发起者、请求编号及业务身份规则；视频任务还核对分P、语言和字幕指纹。路由变化、取消或缓存清除后，旧进度与迟到结果不能覆盖新状态。保留现有活跃任务维护逻辑，后台长任务行为必须在真实扩展中验证。

### 结构校验与业务校验

设置、备份、外部消息和模型结果逐步使用共用结构规则，并从规则推导类型。保留旧字段默认值补齐、词条规范化、未知配置字段剔除及明确的中文错误。正在编辑的草稿允许暂时不完整，在保存边界校验，不能把空数字输入强制改为有效值而吞掉用户输入。

结构合法后仍检查业务关系：删除目标存在、严格模式保留偏好、评论引用属于本次输入、章节连续完整覆盖字幕、会话计划与版本未变化。这些检查随功能维护。

旧离线检查直接导入源码；引入校验依赖后重新核对测试依赖说明。纯业务算法可以继续独立验证，不能让实际依赖库的测试仍被标记为无依赖检查。

| 评论速读 | 同样采用结构化生成与增量对象预览 | 逐步展示总览，不再自行补齐JSON字符串；保留短编号到真实评论的映射、引用验证、部分覆盖说明和完整或部分缓存隔离 |

| 通用AI复核 | 一次完整生成配合结构化输出规范，分类字段使用固定选项规则 | 接管分类结果解析；保留批量编号逐项对应、去重、两个并发、缓存及设置失效。不把整批结果改成单个分类字符串 |
| 阿里云决策复核 | 保留现有专用协议适配；实验性决策接口另见后文 | 不能仅因字段相似就替换供应商；现有概率阈值、独立密钥和业务空间含义保持 |

结构化输出和增量预览由官方接口提供；普通正文采用同一套文本生成入口。[结构化输出说明](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data)、[文本生成说明](https://ai-sdk.dev/docs/ai-sdk-core/generating-text)。

### 公共能力采用方式

| 当前需要 | 现成能力与决定 | 项目仍承担的部分 |
| --- | --- | --- |
| 多供应商调用 | 直接使用已安装的供应商适配包；需要统一模型寻址时使用 `createProviderRegistry`【供应商注册表】，不自建同类注册框架 | 从当前设置构建实例，校验授权、地址、模型和密钥；配置改变后更新实例，不在并发请求中改全局默认供应商 |
| 思考强度 | 优先使用 `reasoning`【跨供应商思考等级】，专属差异使用 `providerOptions`【供应商参数】 | 保留原设置含义，核对开启、关闭和最高等级实际映射；处理不支持参数的警告，不自动把原始思考显示给用户 |
| 思考与生成状态 | 消费 `stream`【包含正文、思考、结束及错误的事件流】，无需自行识别供应商的思考字段 | 转换为当前思考中或生成中状态；只向发起者推送，过滤过期请求 |
| 取消与超时 | 使用 `abortSignal`【取消信号】和 `timeout`【调用超时配置】 | 取消信号仍由页面或后台任务拥有；保留整项任务的总时限，不能让每段新调用重新获得全部任务预算 |
| 请求和流式失败 | 使用标准错误、结束原因及 `onError`【流式错误回调】、`onAbort`【取消回调】 | 中文提示、保留上次结果、清理任务；检查事件流错误，不只依赖外层异常捕获 |

### 结构化结果与版本使用约定

1. 生成中的对象是不完整预览，不能执行建议或写入正式缓存。最终对象验证成功后，还要确认模型正常结束、未取消且业务版本有效；JSON能够解析不代表没有截断。
2. 模型结构规则主要描述可传输的数据结构。本地的词条规范化、跨字段关系、引用归属和章节连续性仍在业务层检查，不把本地转换或校验函数误当供应商支持的生成约束。
3. `supportsStructuredOutputs`【兼容服务是否支持结构约束的适配选项】不能对未知服务默认开启。仅支持JSON模式的服务采用适配包已有能力；完全不支持JSON模式的旧兼容服务，经具体验证后保留普通文本请求与最终JSON校验，不机械替换成另一种仍会请求JSON模式的输出选项，也不自动补发请求。
4. 本版结构化生成统一使用文本生成入口的输出选项，不新增旧式对象生成接口。事件读取优先采用本版 `stream`【完整事件流】和 `onEnd`【结束回调】，避免继续扩散旧别名。平滑转换在本地7.0.142仍通过 `experimental_transform`【流变换接入参数】配置，使用实际类型声明，不猜测参数改名。
5. 本地7.0.142明确区分请求重试和流开始后的重试；前者设为零，后者省略配置。即使把流重试次数设为零，显式开启该选项后错误回调仍可能请求重试，因此不启用这条路径。
6. 供应商使用明确构建的模型实例或已配置的注册表，避免裸模型字符串意外走默认网关。库不会代办扩展域名授权、后台保活或持久恢复。

第3项核对供应商适配的实际能力，第4、5项以已安装包的类型和实现为准。[DeepSeek适配说明](https://ai-sdk.dev/providers/ai-sdk-providers/deepseek)、[兼容服务适配说明](https://ai-sdk.dev/providers/openai-compatible-providers)、[流式生成接口](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text)。

### 实验性决策接口的结论

现有阿里云逻辑同时检查单独置信度和选项概率，二者都达到0.8才允许无关判定。实验性接口中的选项概率与供应商专属置信度不是同一概念，部分适配甚至不返回概率分布；不能只保留一个数值就宣称行为等价。未来取得对应协议适配并完成概率语义、异常、计费与阈值验证后，再考虑替换。[决策接口及概率语义](https://ai-sdk.dev/docs/ai-sdk-core/decisions)、[阿里云模型适配](https://ai-sdk.dev/providers/ai-sdk-providers/alibaba)

## 界面与状态管理

### 品牌和组件使用

保留当前七个设置面板、视频助手五个分页、可拖动评论悬浮窗以及留白首页的主要布局。组件默认颜色与间距映射到现有主题，沿用B站蓝、品牌粉、中性卡片、中文字号与简短文案。

首批基础控件按真实需要选择按钮、输入框、文本域、选择器、开关、复选框、卡片、标签页、折叠区、确认弹窗及提示。AI界面优先选择消息、输入区、生成状态和来源展示。组件源码按需引入；章节跳转、评论定位和建议采用仍是业务专用交互。

模型正文共用一个流式渲染入口，统一中文增强、主题及动画。检查引入的消息组件是否已包含正文渲染，避免重复实现。预览与完成内容使用同一排版基础，但保存状态独立。尊重减少动态效果，用户上翻阅读时不被强制拉回底部。

生成状态沿用当前含义；使用思考组件不自动开放原始模型思考内容。模型文本只作为受控展示内容，保留资源和链接限制，不将返回文本作为脚本或任意页面结构执行。

### 样式隔离与页面挂载

设置页与网页内界面共用主题规则，网页组件的样式、弹层和主题留在扩展自身隔离区域。控件尺寸不能随B站根字号意外变化；避免全局样式重置污染原站。品牌图标继续保留，其他图标可复用风格一致的配套组件。

挂载、监听和卸载各有明确归属。验证键盘焦点、输入法、弹层点击、拖动、窗口缩放、路由切换、全屏退出与扩展失效，确保不会残留监听或挂载多个根。留白首页继续独立早启动，只有自有界面准备好后才切换展示，失败与退出均可恢复原站。

推荐遮罩、播放器菜单与进度标记、评论定位仍直接适配B站原有节点。保留网页初始化等待和恢复规则，避免组件重渲染改写播放器或原站节点。

### 设置页状态

把导航、设置草稿与保存基线、计划写入、分析会话及备份交互分开管理，优先使用现有框架自带状态能力。复杂保存逻辑抽为可直接测试的协调模块，界面状态与后台持久化版本分别维护。

- 普通参数暂停输入约200毫秒后保存；保存中继续编辑，返回结果只更新对应保存基线。
- 同一失败内容不循环重试，修改内容或主动重试后继续；计划保存失败保留输入。
- 空闲页同步外部修改；编辑中的页面保留草稿并暂停冲突保存，重新读取前明确告知影响。
- 本机落盘后返回成功，页面广播异步执行；通知无回应不能占住保存队列。
- 主题独立保存，不触发规则版本更新或模型调用；未保存修改与活跃分析继续保留离开提醒。
