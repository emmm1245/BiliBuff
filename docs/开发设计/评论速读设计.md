# 评论速读设计

当前实现（2026-10-17）：后台评论能力已拆为站点接口、签名限速、引用校验和结果缓存，页面悬浮窗迁为React并复用流式正文。业务采集状态仍由页面协调器拥有，保留暂停续采、部分覆盖、缓存恢复和来源定位；实际浏览器交互尚待实装验证。

## 悬浮窗与内容呈现

评论速读使用可拖动的折叠悬浮窗，默认位于视口右侧，滚动页面时保持可见，不占用推荐栏或评论区的文档位置。点击标题展开或收起，拖动标题栏移动；拖动不触发展开切换，移动和窗口缩放后约束在视口内。默认只显示约49像素高的标题与状态，自动完成不展开、不抢焦点；正文最多占视口七成高度并内部滚动。总览、主要话题、来源链接、值得一看的评论、文本导出依次排列。推荐项先显示AI推荐理由，使用 #00AEEC【B站蓝】；随后显示原评论摘录；底部作者、点赞与定位提示使用 #FB7299【B站粉】。普通点击来源在当前视频页加载、定位并高亮原评论，不刷新播放器。宽度约390像素时窗口限制为视口宽减32像素，长文字换行，不增加窗内横向溢出。复用扩展主题选择，深浅色均保持中性底色；保留卡片自身的点击响应，层级高于现有设置入口，避免按钮遮挡窗内文字。

采集中显示“暂停采集”，隐藏重复的采集按钮；暂停后显示“继续采集”和可用的“分析已采集”。分析期间显示“取消速读”，继续采集暂时禁用。部分结果在总览前注明分析时的已采集数、接口总数和覆盖不完整；继续采集不会悄悄改写已有结果。

已有数据时采集按钮显示“检查更新”，操作后保留计数和内容，核对完成显示新增数量。推荐卡片及话题引用悬停时不加文字下划线，使用与留白模式相同的粉色霓虹边框和柔和外发光；键盘可见焦点同样显示光效并保留焦点轮廓，减少动态效果时关闭过渡。推荐理由与底部蓝粉配色保持原样。

进入视频先显示“读取缓存”，查找期间不自动采集。命中立即显示结果，提示需要更新或导出时点击“检查更新”，不在播放时自动开始采集；计数区显示缓存覆盖范围，与本次采集条数区分。部分缓存仍显示“部分速读”。缓存本身没有原始评论，因此重新速读与导出在手动采集前不可用，并给出操作提示。缓存读取失败显示具体原因，不隐藏异常。

## 修改后检查

分析期间复用计划分析的流式解码与总览提取，通过后台消息只推送至发起标签页的主框架。窗口独立显示“总览 · 生成中”，以纯文本增量更新，不替换整个结果区域、不自动展开或滚动。已有正式结果在本轮分析时暂时隐藏，取消或失败后恢复；只有完整结果通过引用校验才替换并缓存。窗口按请求与视频编号过滤进度，结束、取消、切换视频和修改速读设置后忽略旧进度。

检查真实鼠标展开、拖动与收起，暂停和续采、部分分析、命中缓存后零自动采集、原页定位与未发送草稿保护。桌面深浅色及约390像素窄屏均应保持可读，窗口不能越出视口，推荐项与来源应支持键盘操作。完整历史验证见[扩展评论功能演进](../版本记录/扩展评论功能演进.md)。
