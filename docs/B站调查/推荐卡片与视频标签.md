## 首页推荐数据

页面：<https://www.bilibili.com/>。

“换一换”和滚动追加时观察到推荐接口路径：

```text
https://api.bilibili.com/x/web-interface/wbi/index/top/feed/rcmd
```

响应 `data.item`【推荐条目列表】中观察到：

| 字段 | 用途 |
| --- | --- |
| `bvid` | 视频编号，用于卡片关联和查询标签 |
| `title` | 标题 |
| `duration` | 时长，秒 |
| `pic`、`pic_4_3` | 封面地址 |
| `owner.mid`、`owner.name` | 作者标识与名称 |
| `stat` | 播放、点赞、弹幕等统计 |
| `goto` | 条目类型；样本包含普通视频 `av` 和广告 `ad` |
| `business_info` | 广告业务数据；不要按普通视频结构处理 |
| `room_info`、`ogv_info` | 直播或番剧相关信息槽位 |
| `is_followed` | 是否关注作者 |
| `rcmd_reason` | 推荐理由，例如点赞量提示；不是视频主题标签 |

刷新首页后，检查首屏 10 条推荐的字段，未发现视频标签或分区字段。内联脚本中也未发现常见标签字段。结论仅限于此次页面样本，不应写成“首页永远不能获得标签”。

调试时读取过 `window.__pinia.feed.data.value.recommend.item`【当前页面框架保存的推荐列表】。这是内部状态，可能随站点版本变化；当前脚本不依赖它。不要写入或修改网站内部状态。

滚动还观察到 `/x/web-interface/index/ogv/rcmd`【番剧等独立推荐接口】，并非所有模块都由普通推荐接口提供。第一版不承诺这些独立模块的覆盖。

不要直接复制捕获的完整请求：其中有追踪参数、临时签名和用户关联数据。当前脚本也不主动请求推荐接口。

## 额外查询视频标签：已验证可行

```text
GET https://api.bilibili.com/x/tag/archive/tags?bvid=<视频编号>
```

从首页通过浏览器请求实测，不携带凭据、无需导航到播放页，两次返回 HTTP 200【请求成功状态】和 `code = 0`【业务成功标识】。

- `data`【标签数组】：每项读取 `tag_name`【标签名称】。
- 示例 `BV1N4YX63EEB`【“基因丹药”视频编号】：科普、科幻、天堂、科学、人类、泛知识能量站、基因、科学家、人体。
- 示例 `BV1tSYx66EvP`【《流浪地球：望日》预告片编号】：单机游戏、刘慈欣、射击游戏、流浪地球望日、流浪地球、柳叶刀。
- 两次单次耗时约 54、56 毫秒。没有进行负载、批量吞吐或长期稳定性测试，不能据此推断速率限制。

参考入口：[实测标签接口示例](https://api.bilibili.com/x/tag/archive/tags?bvid=BV1tSYx66EvP)。标签接口属于站点使用的接口，不当作已承诺稳定的公共开放接口。扩展标签请求由[标签服务](../../extension/src/tags.ts)承担。

## 页面结构

| 用途 | 当前实测选择器 |
| --- | --- |
| 首页普通推荐卡片 | `.bili-feed-card .bili-video-card` |
| 首页标题 | `.bili-video-card__info--tit` |
| 首页标题链接 | `.bili-video-card__info--tit a` |
| 播放页相关推荐卡片 | `.video-page-card-small .card-box` |
| 播放页相关推荐标题 | `.info .title`，实测为链接内的段落 |

这些选择器【定位网页元素的表达式】已用于第一版。首页实测命中 10 张卡片；另一次读取播放页返回的网页内容命中 20 张相关推荐，不代表站点数量固定。

首页卡片通常由 `.bili-video-card__wrap`【卡片内容包裹层】包裹内容。隐藏子内容但保留几何尺寸，再覆盖占位层，可以避免页面卡片重排。播放页相关推荐为横向图文布局，遮罩需单独适配。

动态卡片需要同时观察新增节点、标题文字变化和链接变化。网站可能复用原节点展示不同视频；必须用视频编号和标题检查身份变化，清理旧遮罩、旧临时放行状态。首页有封面预览播放，遮罩还需阻断原卡片交互并暂停其中的视频。

## 播放页补充信息

样本：`BV1HBeb6zErf`【“AI数学题！怎么抗起万亿美元的资本泡沫？”视频编号】。

- `window.__INITIAL_STATE__.videoData`【页面初始视频信息】包含简介、标题、分区编号等。
- `tid`、`tid_v2`【两套分区编号】在样本中分别为 201、2098。
- `tname`、`tname_v2`【分区名称】在样本中为空，不能假设可直接读取分区名称。
- `window.__INITIAL_STATE__.tags`【页面初始标签列表】包含“万物研究所、人工智能、学习、数学、Chat GPT、资本”。
- 该视频简介讨论人工智能事件。标签含“学习、数学”并不保证它是课程或习题讲解。
- `related`【相关推荐列表】样本包含标题、作者、封面、时长等，未看到视频标签。
- 网络中观察到 `/x/web-interface/wbi/view/detail`【视频详情接口路径】，尚未独立验证其请求构造；当前脚本不依赖它。

## 首页楼层推荐补查（2026-10-14）

复用现有已登录 Chrome【浏览器】会话，通过 CDP【浏览器开发者协议】只读检查。没有刷新页面、修改账号设置或执行开发中的新版脚本。

页面当时有 58 个 `.bili-feed-card`【普通推荐容器】，其内部均含普通视频卡片；截图中漏处理的卡片位于另一个分区，不能通过扩大普通容器内的标题匹配解决。

| 用途 | 实测选择器或结构 |
| --- | --- |
| 特殊推荐整张卡片 | `.floor-card.single-card`【楼层单卡片】 |
| 外层 | `.floor-single-card`【楼层单卡包裹层】 |
| 内容层 | `.floor-card-inner`【封面和信息主体】 |
| 标题 | `.info-container .title`【信息区标题】，读取其 `title`【完整标题属性】 |
| 标题链接 | `.info-container .title a`【内容跳转链接】 |
| 类别角标 | `.floor-title`【直播、番剧等类别文字】 |
| 后方叠层 | 两个 `.layer`【视觉叠卡层】，其中一个含 `.tiny`【小叠层样式】 |
| 尚未加载 | `.floor-skeleton`【骨架卡片】，没有标题时跳过 |

共发现 16 张楼层卡片，其中 13 张已加载，3 张骨架。已加载类别包含直播、番剧、国创、综艺、课堂、电影、电视剧、纪录片、漫画。

- 直播指向 `live.bilibili.com/<房间号>`【直播间链接】，标题文本可能包含“直播中”提示，因此优先读取完整标题属性。
- 番剧等指向 `/bangumi/play/ep<编号>`【剧集链接】。
- 课堂指向 `m.bilibili.com/cheese/play/ss<编号>`【课程链接】，漫画指向 `manga.bilibili.com/detail/mc<编号>`【漫画链接】。
- 这些样本均不含普通视频卡片和普通视频编号，不能直接套用按视频编号查询标签的接口。此类卡片只按标题过滤，不把类别角标冒充视频标签。
- 新扫描范围同时包含普通推荐和楼层单卡；在整张楼层卡片上遮蔽，使主体和叠层一起隐藏并保留布局。
- 判定缓存身份包含目标链接与标题，防止没有视频编号的不同内容共享空编号而残留临时查看状态。

此轮已验证实际页面结构，未完成新增遮罩与用户交互的安装验收。没有据此声称支持独立直播或番剧播放页。
