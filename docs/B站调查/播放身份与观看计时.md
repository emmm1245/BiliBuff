# 播放身份与观看计时

[文档目录](../README.md)

2026-10-13的初始样本来自用户已登录的桌面浏览器；后续补查日期保留在章节中。以下是对应日期的观察，接口与节点结构可能随站点变化。

本页先保留普通播放页的早期边界，再记录2026-10-14补齐列表播放后的验证。与同轮推广、过滤原因变更共用的完整验收见[广告识别与过滤原因](广告识别与过滤原因.md#验证与安装边界)。

## 观看样本与验证边界

本版使用浏览器媒体播放事件累计时间，不请求账号观看历史。普通播放页通过路径读取视频编号，通过 `h1.video-title`【视频标题节点】读取标题；监听 `#bilibili-player, .bpx-player-container`【主播放器容器】内的视频元素，排除首页封面预览。

上述播放事件接入、短视频结束条件和三页签设置界面尚需实际安装验收。离线模拟测试只验证算法和调用流程，不等于站点不同播放器版本都兼容。未读取用户历史记录、未发送用户数据到模型、未进行真实付费分析。

## 列表播放补齐背景（2026-10-14）

用户确认[播放页初始化与遮罩定位](播放页初始化与遮罩定位.md)中的问题已经解决，随后授权完成视频页推广过滤、补齐观看统计和显示过滤原因。搜索属于主动查找内容，用户明确要求不使用过滤规则；保留现有匹配域名和权限，没有加入搜索页适配。

## 稍后再看与收藏列表观看统计

通过当前站点实测确认：

| 页面 | 路由和当前视频身份 |
| --- | --- |
| 稍后再看 | `/list/watchlater`【稍后再看播放路由】，当前视频编号在查询参数 `bvid`【当前视频编号】中 |
| 收藏夹播放全部 | `/list/ml<编号>`【收藏夹列表播放路由】；打开后自动选择条目并写入同一视频查询参数 |

两者的主视频标题均可从 `h1.video-title`【当前播放标题】读取，主播放器使用 `.bpx-player-container`【播放器容器】；根节点 `#app`【列表应用根节点】在接管完成后不再保留服务端标记，导航挂载状态也符合[播放页初始化与遮罩定位](播放页初始化与遮罩定位.md)的等待条件。

在稍后再看页面选择第二条内容，确认地址中的视频编号、页面标题和选中条目标题同步更新；诊断标签页通过播放事件立即暂停媒体，仅验证页面切换与身份，不以真实播放凑够统计门槛。收藏页面的“播放全部”目标先通过临时捕获打开动作确认路由，再进入专用诊断页检查。

新增 `isListPlayback`【识别已验证的两种列表播放路由】和 `playbackBvid`【读取普通或列表播放页当前视频编号】，用于播放进度和短片结束时的身份检查。普通视频继续从路径读取编号；列表播放从查询参数读取有效编号，缺少编号时不记录。切换视频清空计时基线，不把上一条的时间和标题归给下一条。

统计标准保持不变：实际播放满 30 秒；短片需播放结束且实际播放内容达到时长的九成。暂停、缓冲、拖动不计入，倍速按实际时间统计。列表入口也等待应用节点接管和导航挂载完成，保留列表内容原样。
