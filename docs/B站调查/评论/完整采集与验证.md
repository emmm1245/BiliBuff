## 结论与适用范围

**本轮普通视频样本已验证：“主评论游标遍历＋逐楼回复分页”能够取齐当前账号可见的评论。实际取得 52 条主评论和 92 条楼中楼回复，去重后共 144 条，与接口及页面显示的总数一致。**

这里的“全部”指调查期间当前账号可见、站点接口实际返回的评论，不包含已删除、审核未公开或当前账号无权查看的内容。数量相等也不代表恢复了所有历史评论；本轮确实发现了一条回复指向未返回的父评论。

后续扩展建议以接口结果作为评论数据源，以页面节点作为展示和交互入口。仅抓当前页面文本、只取最热第一页，或者只保存主列表附带的回复预览，都不能得到全部评论。

## 完整采集的最小流程

1. 从当前视频评论组件读取评论类型和对象编号，建立一次采集任务；记录起始总数与时间。
2. 使用最新排序，从空游标读取首批；合并普通主评论与独立置顶，按评论编号去重。
3. 串行使用服务端返回的游标继续读取，直到主列表明确返回结束。每批保存新增评论和进度；未结束但无法继续时标记未完成。
4. 对每个有可见回复的主楼，使用楼中楼接口从第一页开始读取。根据返回总数与页容量确定所需页数，并保存实际取得的唯一回复数。
5. 合并主评论、预览和完整回复时统一去重；楼中楼响应附带的主评论只用于更新已有记录。
6. 核对每楼实际唯一回复数与该楼当前可见计数，再核对全局唯一评论数与接口显示总数；数量变化、请求失败及精选限制都应进入结果状态。

本轮主列表采用原站已有请求层，由内部加载方法完成签名和翻页；楼中楼用页面内的 `fetch`【浏览器网络读取方法】独立验证，采用 `credentials: include`【携带浏览器现有登录态】。没有读取登录凭据来拼装请求，也没有将凭据写入本文件。

本轮楼中楼验证采用串行请求，并在每次响应后约等待1秒，全部返回 HTTP 200【网络请求成功】及业务成功。这个间隔是调查选择，不是平台公布的安全频率。后续发生限流或验证要求时应停止本次采集、保留进度，不进行无限重试。

因为最热分页表现出会话状态，重试或跨浏览器恢复时不能只重放旧游标并假定没有遗漏。实现初期采用同一连续任务和最新排序即可；中断后保留已有编号，重新开始遍历并去重，比假设旧会话仍然有效更容易核验。

## 登录 精选与不可见内容的边界

| 情况 | 当前证据及后续处理 |
| --- | --- |
| 未登录 | 当前脚本在总数超过2且没有登录用户时，把展示列表限制到2条，并在排序、展开回复时引导登录；本轮未退出账号验证服务端的未登录返回范围 |
| 精选评论 | 当前脚本识别 `control.web_selection`【精选评论标记】，以及 `control.show_type`【展示类型】为2时隐藏最新排序；本轮样本不是该场景，不能保证有完整时间线可读 |
| 评论区关闭 | 当前脚本把业务码12061或12002识别为关闭状态；本轮未找到关闭样本验证具体返回文案 |
| 禁止发言 | `control.input_disable`【禁用输入标记】控制输入状态，不能据此认定评论列表为空 |
| 不可见和折叠 | 本轮主评论均未出现已折叠状态；`folder`【折叠状态信息】的展开流程尚未实测，不能声称已覆盖折叠内容 |
| 删除或权限变化 | 只能取得接口当前返回的数据；父评论缺失时保留现有回复，不承诺恢复历史内容 |
| 采集期间有新增或删除 | 分页不是已证实的数据库快照，应记录时间与计数变化，避免把变化误判为程序漏采 |
| 大型评论区与其他页面 | 尚未验证万条评论、动态、番剧、列表播放页等场景，不能把单个普通视频的结果直接扩展到这些页面 |

关于精选、登录限制和关闭状态的说明来自当前站点脚本；关于144条完整获取、重复游标及父评论缺失的说明来自实际网络和数据核对。

## 与现有扩展的衔接

现有 `extension/wxt.config.ts`【扩展配置文件】已经声明B站网页及接口域名权限。`extension/entrypoints/background.ts`【后台消息入口】与 `extension/src/tags.ts`【现有标签请求模块】提供了集中处理只读请求的参考；评论采集应有独立职责，不应混入标签缓存或观看统计。

扩展内容脚本负责读取页面身份、发现评论组件和更新展示；后台负责固定评论接口的数据请求及采集任务。新增消息还需同步考虑 `extension/src/access.ts`【后台调用权限检查】和 `extension/src/types.ts`【消息与数据类型定义】，无需因此扩张成可请求任意网址的通用代理。

扩展内容脚本默认处于 ISOLATED【与页面脚本分隔的执行环境】，可以访问页面节点，但不能直接复用本轮CDP调试中取得的页面变量、组件私有方法或签名函数。因此，“CDP全量验证成功”与“扩展后台已能带相同登录态和签名成功采集”是两项验收。相关规则见 [Chrome内容脚本说明](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

有域名权限的扩展后台可以发起跨域请求，内容脚本仍受页面跨域规则约束；权限本身不证明登录态、签名和站点校验都已适配。下一步只需先验证后台读取一批主评论和两页楼中楼，再实现遍历及计数核对。相关规则见 [Chrome扩展网络请求说明](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。

对用户功能而言，完整采集结果至少需要区分“已完成”“进行中”“部分完成”和“受限”；同时显示已取得数量。后续的过滤、摘要或分析使用哪一范围，再由具体产品需求决定。本轮未新增自动采集、分析或数据保存功能。
