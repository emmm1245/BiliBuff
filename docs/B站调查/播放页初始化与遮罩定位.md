# 播放页初始化与遮罩定位

[文档目录](../README.md)

本文按调查顺序保留2026-10-14的两轮排查。首次仅等待资源加载完成仍会复现；第二轮补齐页面接管及导航挂载条件，并修复卡片定位标记丢失。用户随后确认导航与巨型遮罩问题解决。这里的验证与构建状态均指记录当时。

## 扩展导致视频页导航消失：启动时序调查（2026-10-14）

通过 CDP【浏览器开发者协议】检查用户截图中的公开视频 `BV1uV4y1w7v7`【线代救命第三集的视频编号】，在新建诊断标签页复现，并保留用户原有首页和播放页。

- `#biliMainHeader`【顶部导航挂载容器】仍存在，高度约 64 像素，显示和可见性均正常，但内部节点为空。推荐遮罩仅命中右侧卡片，没有命中导航；这不是隐藏导航的样式规则问题。
- 捕获到网站重复挂载警告，以及 `nextSibling`【读取相邻节点的方法】读取空节点的异常。对导航容器的写入追踪显示：网站导航脚本首次挂载成功，随后第二次挂载先清空容器，再因旧节点已不存在而失败。
- 对照一：只在页面加载阶段移除扩展遮罩和卡片标记，保留扩展按钮；加载完成后停止干预。导航恢复，页面仍有扩展按钮，后续推荐仍能产生遮罩。移除按钮并非必要条件。
- 对照二：加载阶段同时移除按钮和遮罩，导航也恢复。常规加载则重复出现空导航。没有停用其他扩展，因此结论限于本次会话中的时序冲突。

据此判断：在网站接管服务端生成的节点之前插入推荐遮罩，导致页面初始化重建，连带使导航重复挂载。这一因果解释结合节点追踪与对照结果得出；没有声称已经完全分析网站内部框架实现。

首次修改：扩展入口等待 `load`【页面资源加载完成事件】后才读取规则、启动过滤。用户随后反馈仍会复现，说明这次等待条件不足；本轮再次调查和当前修复见下文“严格模式导航丢失与侧栏巨型遮罩：再次调查”。保留原有过滤算法，不修改网站导航脚本，也不添加强制重建导航的补丁。

取舍：首次加载过程中推荐可能短暂可见；本轮优先保障网站正常初始化。该事件不是网站所有后续异步组件都准备就绪的保证，后续页面新增卡片仍由原有观察器处理。

验证：新增 3 项启动时序测试，全部 26 项扩展单元测试、严格类型检查、改动文件的代码规范检查通过。浏览器对照验证了冲突来源；新源码尚未重新构建、重新加载到浏览器，最终安装验收需用户构建后完成。

通过 Context7【技术文档查询工具】核对 [Vue 官方服务端渲染说明](https://vuejs.org/guide/scaling-up/ssr#hydration-mismatch)：实际节点结构和客户端预期不一致时，框架会尝试丢弃错误节点、重新挂载。该说明支持上述机制解释，不能替代本次浏览器实测。

## 严格模式导航丢失与侧栏巨型遮罩：再次调查（2026-10-14）

用户反馈首次时序修复后仍有问题，并明确指出严格模式开启时出现，关闭时正常；新截图显示整块侧栏被“正在等待视频标签”的遮罩覆盖。本轮区分两个缺陷，不把它们都归因于单一加载事件。

### 导航：资源加载结束不等于视频页初始化完成

在新建诊断页只记录节点变化。一次样本中 `load`【资源加载完成事件】约在 2444 毫秒触发，扩展约在 2474 毫秒插入 12 个遮罩；约在 4990 毫秒网站重建节点并移除这些遮罩，随后导航清空。时间仅为该样本，不作为固定延时依据。

另一轮节点追踪发现 `#app`【视频页主应用根节点】初始带有 `data-server-rendered`【服务端已生成页面的标记】，网站接管后移除此标记；导航正式挂载后，`#biliMainHeader`【导航容器】出现 `data-v-app`【导航应用已挂载的标记】，内部包含 `.bili-header__bar`【导航内容条】。

当前修复：普通视频页在资源加载完成后，还需同时确认主应用已移除服务端标记、导航应用已挂载且内容条存在，才启动过滤。等待通过节点观察实现，不依赖固定秒数；扩展失效时断开观察、不继续启动。首页仍保留原有资源加载等待。

浏览器对照：在上述条件满足前临时移除诊断页遮罩，满足后允许恢复；导航保留，严格模式仍有推荐遮罩。没有再出现重复挂载或相邻节点异常。该对照使用浏览器临时干预验证等待条件，尚不是重新构建后的扩展端到端验收。

### 侧栏：网站重写卡片标记后，绝对定位参照发生变化

用户现有页面实测：遮罩父节点仍是 `.card-box`【单张推荐卡片】，但 `.bf-card`【扩展卡片定位标记】和 `.bf-related`【横向卡片标记】已丢失，仅剩 `.bf-blocked`【遮蔽标记】。此时父卡片为静态定位，约 80 像素高，遮罩实际参照 `.right-container-inner`【整个侧栏容器】定位，约 2932 像素高。

原代码只在首次发现卡片时添加定位和横向标记，网站后续重写类名时不会补回；原观察器也不监听类名变化。

当前修复：

- 遮蔽标记本身也提供相对定位，保证卡片仍被遮蔽时，遮罩的定位参照不会落到整个侧栏。
- 每次扫描都检查并补回定位、横向标记，覆盖已经存在的卡片。
- 观察已追踪卡片的类名变化，并排除类名实际未变化的记录，避免扩展自身重复写入触发持续扫描。

浏览器临时验证：11 个遮罩的定位参照均回到自己的父卡片，高度约 80–82 像素；模拟再次清掉定位和横向标记后，标记自动恢复，遮罩尺寸仍与卡片一致，导航保持存在。

新增两项视频页初始化等待测试，全部 28 项扩展单元测试、严格类型检查、三个改动源码/测试文件的代码规范检查通过。新源码仍需用户重新构建、在扩展管理页重新加载并刷新 B 站后验证。没有更改严格模式规则或自动放行未确认内容。
