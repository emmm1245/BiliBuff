## 调查后的实施（2026-10-18）

用户批准后，播放地址已迁至 `/x/player/wbi/playurl`【签名播放地址】，共用已有签名算法，导航公共签名信息缓存1小时；未登录但导航仍返回公共密钥时可正常签名。合并文件与分离音视频顺序获取，遇访问限制停止后续格式查询，不回退旧入口；若已经取得可用格式仍保留。

普通过滤和AI选片标签均已迁至 `/x/web-interface/view/detail/tag`【带标签类型的列表】，排除背景音乐、保留主题与话题，继续使用原有缓存、去重和并发。普通过滤继续不携带登录凭据。缓存读写失败单独记录，不丢弃已经取得的有效标签，也不误判为来源受限。

新增共用的来源冷却及最近200条脱敏请求诊断，并接入原有日志导出、清除入口。视频助手、普通标签与AI选片可共享相关来源的限制，AI选片保留自身并发、间隔和预算；评论调度保持原实现。清除诊断不会清除冷却。其他经过对照仍正常的接口保留，未增加配置项或依赖。

验证分两部分：下节28次真实接口对照验证了迁移目标的响应兼容；本次修改通过50个测试文件、511项离线测试，以及类型检查和代码规范检查。新增实现尚需用户构建并重新加载后，才能对实际安装版做浏览器回归，不能将此前的接口对照当作新版扩展验收。

## 实施前的扩展接口全面复查（2026-10-18）

本节针对搜索旧接口曾出现412的问题，盘点当前源码全部11类B站API，对照已安装扩展的真实请求、B站原生页面和正在加载的官方脚本。没有修改接口实现、配置或身份，没有发起下载、互动写入或额外模型分析；本轮仅更新调查文档。

结论：播放地址和视频标签仍使用网页已换用的旧入口，值得计划迁移；本轮没有复现它们故障。其余接口不能仅凭路径不含WBI【B站网页请求签名】就判旧，也不能因带WBI就判定必须签名。更普遍的不足是各模块错误分类、日志与冷却不一致，未来出现访问限制时可能难以定位。

### 下一步建议及验收

1. 优先将播放地址迁至已经对照通过的签名入口，保留现有合并文件/分离流格式选择、权限检查、分P校验及资源域名校验。验收至少覆盖两类格式、允许的清晰度、重新获取地址和访问限制时停止；不要在412后自动切换另一入口继续请求。
2. 补齐视频助手和标签请求的脱敏诊断及相应来源冷却。AI选片已有逐请求状态和10分钟冷却，评论已有独立持久冷却；通用视频请求目前只有错误文字、没有相同来源的持续冷却，标签把网络、业务、解析与缓存写入失败汇成一类并等待30秒。建议共用小型错误分类/日志能力，保留各模块正常交互和不同来源隔离，不把所有功能强塞进一套选片预算。
3. 标签按新类型迁移时明确仅主题/话题参与现有主题判定，背景音乐不自动参与。保留缓存、去重、并发和偏好语义；用带背景音乐、话题和普通主题的样本核对，不能因为新接口多返回文字就视为推荐更准确。
4. 详情、相关推荐、搜索联想、评论及搜索历史入口保留。播放器信息是否统一加签名作为后续一致性改进，不作为本轮已复现故障修复。不要为了“全是新版”而改动正常接口。

没有对接口实施改动，因此本轮不要求重新构建，也没有重复跑代码测试。临时播放页始终暂停，测试页、保活和完整响应已清理；没有保存Cookie值、账号信息、播放授权URL或评论正文。短时成功不能证明未来永不受限，现有搜索412的服务器唯一触发规则仍未确定。

顶部收藏、历史、动态、消息均有独立入口。仅检查入口和页面结构，没有展开读取私信内容。分辨率、字幕、单集循环、自动开播、镜像、关灯等播放器选项本轮只确认存在，不代表已验证它们与扩展的全部组合。

搜索初始结果可能来自页面内初始数据；本轮资源记录中只看到搜索默认词请求，不能据此推断搜索结果接口的构造。历史、番剧、直播间的完整请求参数、响应字段和交互流程未穷尽。

后续建议，均不属于此次修复已实现的功能：

1. 优先补齐视频页明确推广卡片，继续保留原尺寸和临时查看能力；先覆盖实际广告容器，再验证广告开关是否立即生效。
2. 支持稍后再看和收藏列表播放的观看计时，统一读取当前播放内容身份；保持分集、切换、暂停和倍速的计时语义。当前仅按普通视频路径读取编号会漏计。
3. 热门可考虑单独可选适配。用户后来明确要求搜索结果保留原样，因此搜索不接入过滤规则，也不为此增加搜索子域名权限。
4. 再考虑动态和作者投稿，按明确的普通视频卡片定位；每种页面保留自己的标题与容器读取方式，避免全站通用选择器误伤导航、合集和评论。
5. 收藏、历史默认保留，未来可以提供判定说明或可选过滤；不因它们使用相同卡片类名就自动接入首页规则。
6. 番剧、直播作为独立内容类型规划；主题标签、季/集/房间身份、权限和观看统计均需重新定义，不能把首页楼层卡片标题匹配当作完整适配。

持续验收重点：冷启动导航完整、首页加载和滚动、普通视频直达与合集切换、规则更新、播放器显示模式、动态内容身份变化，以及扩展失效清理。此次没有新增站点权限或实现这些扩展方向。
